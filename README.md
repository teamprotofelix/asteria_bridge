# ASTERIA II — Horizon Bridge v2.0

아스테리아-2 심우주 항해 시뮬레이션. 서버·API 키·CDN·npm 설치가 없는 정적 사이트입니다. 전후좌우 및 상하 360° 관측을 지원하는 6면 큐브맵의 3D 원근 렌더링과, 실제 3차원 기하를 레이캐스팅해 제작한 함교 내부 WebP를 합성합니다. 관측 위치는 함교 중앙에 고정되며, 함교를 걸어다니는 6DOF 게임은 아닙니다.

## 시작하기

- ZIP을 압축 해제하고 `index.html`을 브라우저에서 여세요. 모든 상대경로 에셋을 같이 유지하세요. 브라우저의 로컬 파일 접근 정책에 따라 정적 HTTP 호스팅이 필요할 수 있습니다.
- GitHub Pages: 저장소 루트에 `index.html`, `app.js`, `style.css`, `.nojekyll`, `assets/`를 업로드합니다. Settings → Pages → Deploy from a branch → main / (root) → Save.
- 별도 빌드 과정 없음. 일반 정적 호스트 또는 로컬 `python -m http.server 8000`으로도 실행할 수 있습니다.

## 조작법

| 입력 | 기능 |
|---|---|
| WASD / 화살표 | 상하좌우 연속 회전 (각도 제한 없음) |
| 마우스 / 터치 드래그 | 시야 회전 |
| Q/E | 롤 360° |
| 마우스 휠 / +, - | 시야각 확대/축소 |
| R / 더블 클릭 | 정면 복귀 및 롤 초기화 |
| C / Esc | 관측 모드 / 종료 |
| 자동 시야 | 일정 속도로 수평 자동 회전 |
| 함교 ON/OFF | 3D 함교 구조 표시/숨기기 |
| 항해 → | 선택한 목적지 텍스처를 로드하고 워프 |
| 우주 상황 | 선택한 12초 상황 재생; 자동 상황을 켜면 간헐적으로 발생 |

## 탐사 구역 (9)
NEREID(고리형 가스 행성), SELENE(빙하 행성), EOS(암석 행성), DEEP SPACE(심우주), GAIA(지구형 행성), SOLARIS(항성), SINGULARITY(블랙홀), ASTEROID BELT(소행성대), NEBULA(성운).

우주 상황 6종: 유성우, 소행성 통과, 혜성 조우, 태양 폭풍, 미확인 신호, 탐사선 조우. 레이더·보호막·항해 속도는 시뮬레이션 수치입니다.

## 렌더링

- WebGL 큐브맵 레이 렌더러: 가속 가능 기기에서 선형 보간. GPU 컨텍스트 실패/손실 시 Canvas CPU 방식으로 전환.
- Canvas 360°: 화면 픽셀을 시야 방향에 따라 6면 텍스처로 역투영하여 실제 전방위 연속 시야 제공. 움직일 때 낮은 렌더 해상도, 정지하면 높은 렌더 해상도. WebGL 없는 브라우저에서도 동작.
- 함교와 우주를 별도 레이어에 렌더링해 동적 이벤트가 창문 뒤로 나타납니다. 360° 회전은 카메라 시점 회전이며 함선의 물리 궤도/공간 이동을 수치 적분하는 것은 아닙니다.
- 8192×4096 성운·별 파노라마 원본, 4096×2048 표면 텍스처 5개, 1536×1536 우주 큐브맵 54개, 2048×2048 투명 함교 큐브맵 6개. 8K/4K 원본은 에셋 제작용이며 웹 실행 시에는 6면 최적화 텍스처를 사용합니다.
- 에셋은 절차적 합성 및 3D 기하 렌더링으로 자체 제작한 허구의 천체 이미지이며 실제 NASA 사진이나 정확한 천체물리 시뮬레이션이 아닙니다.
- Python 제작 스크립트: `assets/build_v2.py`, `assets/render_bridge.py` (Python/Pillow/NumPy/SciPy 필요). 실행에는 Python이 필요하지 않습니다.

## 검증 범위

Chromium PC 1440×900 및 모바일 390×844, 키보드·목적지 워프·우주 이벤트·관측 모드·화면 경계 등을 Canvas 렌더러에서 확인했습니다. 테스트 환경은 로컬 파일 URL과 임의 HTTP URL 접속을 차단하므로 동일 HTML/CSS/JS와 WebP를 데이터 URL로 연결해 브라우저에서 검사했습니다. 실제 WebGL 가속과 GitHub Pages 운영 배포, 실물 모바일 하드웨어는 미검증입니다.
